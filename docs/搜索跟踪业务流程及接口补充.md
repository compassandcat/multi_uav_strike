# 搜索跟踪业务流程及相关接口

## 1. 工作模式设置 MAV_CMD_SET_WORKMODE

首页点击"搜索跟踪"按钮，进入该工作模式：

地面向机载端发送 `command = 51000` 的 `COMMAND_LONG` 自定义 mavlink 指令，定义如下：

| 字段             | 类型     | 单位 | 说明                                                 |
| ---------------- | -------- | ---- | ---------------------------------------------------- |
| target_system    | uint8_t  | -    | 目标系统 ID                                          |
| target_component | uint8_t  | -    | 目标组件 ID                                          |
| command          | uint16_t | -    | 51000                                                |
| confirmation     | uint8_t  | -    | 确认标志（首次发送为 0）                             |
| param1           | float    | -    | 0，1，2，3 // 即察即打，搜索跟踪，搜索打击，据止搜索 |
| param2           | float    | -    | 0，1 // 0 全局坐标系，1 本地坐标系                   |
| param3~7         | float    | -    | 未使用（保留）                                       |

机载端收到后需要回复对应的 `COMMAND_ACK`。

设置成功后，页面左上角会标注当前工作模式。

## 2. 任务流 CLUSTER_MISSION_CTL

用户可以选择任务预案编辑任务流，完成任务流中每项任务配置后，点击完成编辑，再点击预案，选择执行预案的无人机，点击确认。

也可通过单个即时任务，进行参数配置，区域选择（若该任务需要），分配无人机后，点击确认。

地面站会统一通过 kcp 发送：

- **消息名称**：CLUSTER_MISSION_CTL
- **消息 ID**：0x1001

具体消息定义如下：

### 2.1 传输协议分层

| 层       | 说明                                                         |
| -------- | ------------------------------------------------------------ |
| UDP 外层 | Magic(2B, 0xABCD) + Type(1B) + PayloadLen(4B)；（KCP 下层承载） |
| KCP 层   | KCP 协议自行封包，业务层无需关心                             |
| 业务层   | 本规范定义的可变长二进制帧，携带设备 SN 和 JSON 格式的任务数据 |

### 2.2 业务层帧头字段

| 偏移 | 字段       | 长度 | 字节序 | 说明                         |
| ---- | ---------- | ---- | ------ | ---------------------------- |
| 0    | Magic      | 2    | 大端   | 固定值 0xABEF，用于帧同步    |
| 2    | Version    | 1    | —      | 固定值 1                     |
| 3    | MsgID      | 2    | 大端   | 消息类型，本消息为 0x1001    |
| 5    | SNLen      | 2    | 大端   | SN 字段的字节长度            |
| 7    | PayloadLen | 4    | 大端   | Payload 的字节长度           |
| 11   | SN         | 变长 | —      | 目标设备序列号，UTF-8 字符串 |
| —    | Payload    | 变长 | —      | 任务数据，UTF-8 编码的 JSON  |

### 2.3 Payload 数据结构（JSON Schema）

Payload 为一个 JSON 对象，即技能编排，顶层结构如下：

```json
{
  "skill_flow_id": "<string>",
  "devices_sn": ["<string>"],
  "skills": [<skill>, <skill>, ...],
  "constraints": { "fence": [...], "threat_area": [...] }
}
```

| 字段 | 类型 | 必填 | 说明 |
|------|------|------|------|
| skill_flow_id | string | 是 | 技能编排的唯一标识，同一批次下发给同一设备的多个 skill 共享此 ID |
| devices_sn | string[] | 是 | 目标设备 SN 列表（具有相同技能编排的设备 SN 列表） |
| skills | object[] | 是 | 有序的原子技能（单个任务）列表，按数组顺序依次执行，元素可单个，可多个 |
| constraints | object | 否 | 约束条件，包含围栏(fence)和威胁区域(threat_area) |

### 2.4 原子技能 skill（单个任务）

```json
{
  "skill_type": <int>,
  "skill_id": "<string>",
  "skill_ctl": 1,
  "devices_sn": ["<string>"],
  "arrive_path": <waypoints>,
  "skill_area": <area>,
  "skill_area_path": [<device_waypoints>, ...],
  "skill_area_flag": <int>,
  "skill_params": <skill_params>
}
```

| 字段 | 类型 | 必填 | 说明 |
|------|------|------|------|
| skill_type | int | 是 | 技能类型（见 2.5 枚举） |
| skill_id | string | 是 | 技能唯一标识 |
| skill_ctl | int | 是 | 执行控制：1=上传部署(默认立即执行) 2=暂停 3=恢复 0=停止 |
| devices_sn | string[] | 是 | 执行该技能的所有目标设备 sn |
| arrive_path | object | 否 | 到达任务区域前的航线（waypoints） |
| skill_area | object | 否 | 任务执行区域 |
| skill_area_path | object[] | 否 | 任务区域内的航线，按设备 SN 分发 |
| skill_area_flag | int | 是 | 区域描述方式：0=无区域，skill_area 无效；1= skill_area 有效，描述区域，不做区域内航线生成；2= skill_area_path 有效，区域内生成的航线，对应每个设备；3= skill_area 和 skill_area_path 两者均有效 |
| skill_params | object | 是 | 技能执行参数（见 2.6） |

### 2.5 skill_type 枚举

| 值 | 名称 | 说明 |
|----|------|------|
| 100 | EJ_Takeoff | 弹射起飞 |
| 101 | Gather | 集结 |
| 102 | Search | 搜索 |
| 103 | Return | 返航 |
| 104 | Relay | 中继（暂不实现） |
| 105 | Attack | 多目标打击 |
| 106 | GR_Takeoff | 地面起飞 |

### 2.6 skill_params 参数

| 字段 | 类型 | 单位 | 说明 |
|------|------|------|------|
| takeoff_height | float | m | 起飞到达高度（包括弹射起飞和地面起飞） |
| takeoff_speed | float | m/s | 起飞速度（包括弹射起飞和地面起飞） |
| takeoff_time_interval | float | s | 弹射时间间隔 |
| gather_speed | float | m/s | 集结速度 |
| gather_height | float | m | 集结高度 |
| search_arrive_speed | float | m/s | 搜索区域前往速度 |
| search_speed | float | m/s | 搜索速度 |
| search_height | float | m | 搜索高度 |
| safe_distance | float | m | 安全距离 |
| formation | int | - | 队形（针对搜索任务）：0 一字形，1 圆形，2 无编队；打击方式（针对多目标打击任务）：0 默认打击，1 惯序打击，2 协同/编队打击 |
| return_speed | float | m/s | 返航速度 |
| return_height | float | m | 返航高度 |
| attack_speed | float | m/s | 打击速度（针对多目标打击） |
| target_type | int (目前是 uint8_t) | - | 目标类型（针对搜索任务），暂定 0000 0001 代表人，0000 0010 代表车，那么 0000 0011 代表人和车 |
| max_duration | float | s | 技能最长执行时长 |

### 2.7 航线 waypoints

其中 seq 是预留的冗余标识，一般填 0。

```json
{
  "frame": 0,
  "points": [
    {
      "x": <double>,
      "y": <double>,
      "z": <double>,
      "seq": <int>,
      "params": [<float>, ...],
      "actions": [
        {
          "action_type": <int>,
          "action_params": [<float>, ...]
        }
      ]
    }
  ],
  "global_params": [<float>, ...]
}
```

| 字段 | 类型 | 说明 |
|------|------|------|
| frame | int | 坐标系：0=WGS84 1=WGS84相对高度 2=WGS84地形高度 10=LOCAL_ENU 11=LOCAL_NED 20=BODY_FRD 30=MAP |
| points[].x | double | 纬度（°），当 frame=0 |
| points[].y | double | 经度（°），当 frame=0 |
| points[].z | double | 高度（m），当 frame=0 |
| points[].seq | int | 航点序号 |
| points[].actions[].action_type | int | 航点动作类型 |
| points[].actions[].action_params | float[] | 航点动作参数 |
| global_params | float[] | 航线全局参数 |

### 2.8 区域 area

```json
{
  "type": <int>,
  "data": [<double>, ...]
}
```

| type | 含义 | data 格式 |
|------|------|-----------|
| 0 | 点 | [lat, lon] |
| 1 | 圆 | [lat, lon, radius, _] |
| 2 | 多边形 | [lat1, lon1, lat2, lon2, ...] |

### 2.9 设备航线 device_waypoints

```json
{
  "device_sn": "<string>",
  "waypoints": <waypoints>
}
```

将航线与设备 SN 绑定，skill_area_path 中每条航线对应一台设备。

### 2.10 约束条件 constraints

```json
{
  "fence": [<area>, ...],
  "threat_area": [<area>, ...]
}
```

| 字段 | 说明 |
|------|------|
| fence | 电子围栏区域列表，禁止进入 |
| threat_area | 威胁区域列表 |

### 2.11 指令确认

- **消息名称**：CLUSTER_MISSION_ACK
- **消息 ID**：0x1003
- **方向**：从机载反馈回地面站

机载端收到 kcp 任务消息后，应回复地面站 ack 消息，具体消息定义如下：

#### 2.11.1 传输协议分层

| 层 | 说明 |
|------|------|
| UDP 外层 | Magic(2B, 0xABCD) + Type(1B) + PayloadLen(4B)；（KCP 下层承载） |
| KCP 层 | KCP 协议自行封包，业务层无需关心 |
| 业务层 | 本规范定义的可变长二进制帧，携带设备 SN 和 JSON 格式的任务数据 |

#### 2.11.2 业务层帧头字段

| 偏移 | 字段 | 长度 | 字节序 | 说明 |
|------|------|------|--------|------|
| 0 | Magic | 2 | 大端 | 固定值 0xABEF，用于帧同步 |
| 2 | Version | 1 | — | 固定值 1 |
| 3 | MsgID | 2 | 大端 | 消息类型，本消息为 0x1003 |
| 5 | SNLen | 2 | 大端 | SN 字段的字节长度 |
| 7 | PayloadLen | 4 | 大端 | Payload 的字节长度 |
| 11 | SN | 变长 | — | 目标设备序列号，UTF-8 字符串 |
| — | Payload | 变长 | — | 任务数据，UTF-8 编码的 JSON |

#### 2.11.3 Payload 数据结构（JSON Schema）

任务下发收到后的反馈内容：

```json
{
  "skill_flow_id": "<string>",
  "code": "<int>"
}
```

| 字段 | 类型 | 必填 | 说明 |
|------|------|------|------|
| skill_flow_id | string | 是 | 技能编排的唯一标识 |
| code | int | 是 | 反馈的状态码，枚举为：0=成功 1=解析失败 |

### 2.12 关键约定

1. **skills 有序执行**：skills 数组有序，设备应按数组顺序依次执行每个技能，前一个完成后进入下一个。
2. **可选字段为 null 时写为缺省**：arrive_path、skill_area、skill_params 等可选字段，若不存在则在 JSON 中不出现该 key，而非设为 null。
3. **约束区域在技能间共享**：constraints 作用于整个 skill_flow，所有 skills 均需遵守。

## 3. 飞行模式设置 MAV_CMD_CTRL

若进行弹射起飞任务，需先对无人机设置弹射模式 `COMMAND_LONG(76)`，设置好弹射模式的飞机才能执行弹射起飞，否则只能执行地面起飞。

地面站发送 `command = 50000` 的 `COMMAND_LONG` 自定义 mavlink 指令，消息定义如下：

| 字段 | 类型 | 单位 | 说明 |
|------|------|------|------|
| param1 | float | - | ctl_type，固定值 10（set_mode） |
| param2 | float | - | 模式编号 |
| param3~7 | float | - | 保留，填 0 |

机载端收到后需要回复对应的 `COMMAND_ACK`。

关于模式编号的说明：

**地面站统一模式定义以及 PX4 映射关系（PX4 模式向统一模式映射）：**

| 统一模式名称 | 统一模式值 | 统一模式含义 | px4 模式 |
|--------------|------------|--------------|----------|
| MANUEL | 1 | 手动控制 | Manual、Stabilized、Acro、Altitude、Position |
| HOLD | 2 | 保持 | Hold |
| MISSION | 3 | 自主任务执行 | Mission、Follow Me、Orbit |
| EXTERNAL | 4 | 外部实时控制 | Offboard |
| RTL | 5 | 返回 | Return |
| LADNING | 6 | 结束运行 | Land |
| EMERGENCY | 7 | 紧急控制 | Termination |
| LAUNCH | 8 | 启动 | Catapult Launch（弹射模式，待确认） |

**地面站设置统一模式下的 PX4 默认模式（统一模式向 PX4 模式映射）：**

| 统一模式名称 | 统一模式值 | 统一模式含义 | px4 默认模式 |
|--------------|------------|--------------|--------------|
| MANUEL | 1 | 手动控制 | Position |
| HOLD | 2 | 保持 | Hold |
| MISSION | 3 | 自主任务执行 | Mission |
| EXTERNAL | 4 | 外部实时控制 | Offboard |
| RTL | 5 | 返回 | Return |
| LADNING | 6 | 结束运行 | Land |
| EMERGENCY | 7 | 紧急控制 | Termination |
| LAUNCH | 8 | 启动 | Catapult Launch（弹射模式，待确认） |

## 4. 设备任务状态 CLUSTER_MISSION_STATE

机载收到地面站发送的任务消息，需发送 kcp 消息上报每架无人机当前正在执行的技能，以便地面站跟踪各设备的任务执行进度。

- **消息名称**：CLUSTER_MISSION_STATE
- **消息 ID**：0x1002

| 偏移 | 字段 | 类型 | 字节数 | 说明 |
|------|------|------|--------|------|
| 0 | magic | uint16 | 2 | 大端，固定值 0xABEF |
| 2 | version | uint8 | 1 | 固定值 0x01 |
| 3 | msg_id | uint16 | 2 | 大端，0x1002 |
| 5 | sn_len | uint16 | 2 | 大端，设备 SN 字符串长度 |
| 7 | payload_len | uint32 | 4 | 大端，body 的 JSON 长度 |
| 11 | sn | string | sn_len | 设备序列号 |
| 11+sn_len | payload | string | payload_len | JSON（见下方） |

**Payload JSON 结构（定频上报当前执行的技能类型）：**

```json
{
  "skill_flow_id": "flow-uuid",
  "skill_id": "skill-uuid",
  "skill_type": 1,
  "state": 0
}
```

| 字段 | 类型 | 说明 |
|------|------|------|
| skill_flow_id | string | 当前任务流 ID，与下发指令中的 skill_flow_id 对应 |
| skill_id | string | 当前正在执行的技能 ID，与下发指令中的 skill_id 对应 |
| skill_type | int | 当前正在执行的技能类型（见 2.5 枚举） |
| state | int | 当前技能执行状态（0=未开始, 1=执行中, 2=暂停, 3=完成 等） |

## 5. 跟踪状态回传 TRACKING_STATE

搜索过程中，若无人机识别到目标并进入跟踪状态，需要通过自定义 mavlink 消息，将跟踪状态回传给地面站，地面站收到消息后，会高亮并闪烁对应无人机状态卡片，提示操作人员。

**自定义状态消息 TRACKING_STATE，msg id = 43000**

| 字段 | 类型 | 单位 | 说明 |
|------|------|------|------|
| time_boot_ms | uint64_t | ms | 系统启动后的时间戳 |
| tracking_state | uint8_t | - | 跟踪状态（0=未跟踪，1=跟踪中） |

## 6. 视频流开启与关闭 MAV_CMD_MEDIA_SWITCH

操作人员注意到高亮且闪烁的无人机，手动选择并打开该无人机第一视角视频流，并通过切换视图按钮放大，进入第一视角大屏，也可根据需要调整视频源。

地面站需发送 `command = 50003` 的 `COMMAND_LONG` 自定义 mavlink 指令，主动请求某架无人机的第一视角视频流，天空端接收到请求后，将指定无人机的视频流，按双方提前约定好 rtmp 地址格式，推送到地面站流媒体服务器，地面站前端从本地流媒体服务器拉取视频流进行播放。

**rtmp 地址格式**：`rtmp://{net_ip}:1935/{sn}/live/stream{camera_id}/{channel}`

**自定义 COMMAND_LONG 指令 MAV_CMD_MEDIA_SWITCH，消息定义如下：**

| 参数 | 类型 | 单位 | 说明 |
|------|------|------|------|
| target_system | uint8_t | - | 目标系统 ID（天空端） |
| target_component | uint8_t | - | 目标组件 ID |
| command | uint16_t | - | 指令 ID（50003） |
| param1 | float | - | camera_id：0,1,2 |
| param2 | float | - | switch：0=关闭推流, 1=开启推流 |
| param3 | float | - | channel：0=可见光 1=红外 2=带算法框的视频流 3=点云 |
| param4~7 | float | - | 未使用（保留） |

机载端收到后需要回复对应的 `COMMAND_ACK`。

## 7. 跟踪模式下的对目标的处理 MAV_CMD_ATTACK

操作人员在第一视角大屏下，确认目标并进行操作，打击/忽略/暂存，取消打击。

地面站需发送 `command = 51001` 的 `COMMAND_LONG` 自定义 mavlink 指令 `MAV_CMD_ATTACK`，自定义指令消息定义如下：

| 参数 | 类型 | 单位 | 说明 |
|------|------|------|------|
| target_system | uint8_t | - | 目标系统 ID（天空端） |
| target_component | uint8_t | - | 目标组件 ID |
| command | uint16_t | - | 指令 ID（51001） |
| param1 | float | - | 0=打击，1=忽略，2=暂存，3=取消打击 |
| param2 | float | - | 打击速度，m/s（可以考虑在通用配置中列一栏搜索跟踪打击配置） |
| param3~7 | float | - | 未使用（保留） |

机载端收到后需要回复对应的 `COMMAND_ACK`。

## 8. 载荷类型 PAYLOAD_STATUS_COMMON

若操作人员选择打击，地面站需事先知道该无人机是否具备打击能力，需机载端通过自定义 mavlink 消息，将设备载荷状态上报给地面站，用于地面站通过载荷类型区分无人机类型，进而判断是否可用于执行某项任务。

**自定义状态消息 PAYLOAD_STATUS_COMMON，msg id = 43000**

| 字段 | 类型 | 单位 | 说明 |
|------|------|------|------|
| field_flags | uint8_t | - | 有效字段掩码，目前置为 0 即可 |
| payload_type | uint8_t | - | 雷达 RADAR=5，通信中继 COMM_RELAY=6，弹药 MUNITION=7 |
| payload_state | uint8_t | - | 载荷运行状态：0=未激活, 1=激活/运行中（默认为 1 即可） |
| fault_code | uint16_t | - | 故障/错误码，0 表示无故障 |
| temperature | float | degC | 载荷温度（摄氏度）（如不需要，给 0 即可） |

## 9. 目标详情和图片回传 DEVICE_TARGETS

- 打击成功执行后，机载端需通过 kcp 向地面站回传一帧目标图片和目标详情，并标明目标状态是"已打击"。
- 暂存成功执行后，机载端需通过 kcp 向地面站回传一帧目标图片和目标详情，并标明目标状态是"已跟踪"。

**kcp 消息 DEVICE_TARGETS，msg_id=0x2001**，具体定义如下：

### 9.1 UDP 外层

| 偏移 | 字段 | 类型 | 字节数 | 说明 |
|------|------|------|--------|------|
| 0 | magic | uint16 | 2 | 固定魔数 0xABCD（大端） |
| 2 | type | uint8 | 1 | 包类型：1=握手请求, 2=握手应答, 3=KCP 数据, 4=KCP 心跳 |
| 3 | payload_len | uint32 | 4 | 后续 KCP 数据的字节长度（大端） |

### 9.2 业务层

| 偏移 | 字段 | 类型 | 字节数 | 说明 |
|------|------|------|--------|------|
| 0 | magic | uint16 | 2 | 固定魔数 0xABEF（大端） |
| 2 | version | uint8 | 1 | 协议版本号，当前为 1 |
| 3 | msg_id | uint16 | 2 | 消息类型：0x2001 = DEVICE_TARGETS（大端） |

| 7 | payload_len | uint32 | 4 | Body 部分的字节长度（大端） |
| 11 | sn | char[] | sn_len | 设备序列号字符串 |
