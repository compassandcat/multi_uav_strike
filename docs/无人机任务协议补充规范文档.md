# 无人机任务协议补充规范文档
## 一、起飞类任务逻辑协议
### 1.1 弹射起飞任务
1. 飞行逻辑：仅依据起飞高度与合理位置悬停，到达设定高度后立即切换至后续任务；可控完成后即刻执行下一任务；弹射起飞后续一定会也一定要带其他任务，否则不允许进入弹射起飞。
2. 模式与状态回传规则
    - 上报标识：是否执行弹射起飞模式的协议使用4.14 CLUSTER_MISSION_STATE中的state；
    - 供电板执行弹射起飞时，4.14报文反馈**执行中**；航点跟踪阶段同样标记执行中；仅抵达最后一个航点时标记任务完成；
3. 强制约束：弹射起飞任务**必须配置后续接续任务**，不允许无后置任务单独存在。

### 1.2 地面起飞任务
1. 高度约束：仅判定起飞高度阈值，到达阈值则任务完成；
2. 水平约束：全程保持当前水平坐标，不做位置机动。

## 二、集结/搜索/返航基础通用规则
1. 集结任务：任务执行完成后**自动终止，等待触发指令再继续后续任务（如果有）**；
2. 任务区定义：集结、搜索、返航三类任务均配置独立任务执行区域；
3. 返航任务逻辑：仅沿预设航点飞行，抵达最终航点自动执行降落流程。

## 三、全任务统一速度指令规范
1. 所有任务必须携带速度指令参数（目前集结、返航、搜索即航点跟踪有速度指令，在9.2.6中，跟踪与打击速度目前协议里没体现后续会加上）；
2. 两段速度区分逻辑（这个目前也没有实现，不过后续需要实现）
    - 抵达任务区前：使用巡航速度；
    - 进入任务执行区内：切换为任务专属速度；
3. 模式激活时序：完成任务区内第一个航点飞行后，再开启当前任务所需对应功能模式。

## 四、目标识别与目标操作协议
### 4.1 目标类型 target_type（uint8 位运算）
依据协议9.2.6定义，通过位运算解析识别目标类别，用于地面站回传目标基础属性（当前为int8，需修改为uint8）。

### 4.2 目标操作类型 DetectObject.type
协议11.2.1.2原DetectObject type字段语义修改，代表对目标的操作行为，枚举定义：
| 枚举值 | 操作类型 | 说明                            |
| ------ | -------- | ------------------------------- |
| type=3 | 一般目标 | 仅搜索识别，无持续跟踪/打击动作 |
| type=2 | 跟踪目标 | 曾被视觉跟踪的目标              |
| type=1 | 打击目标 | 下发打击指令执行攻击流程        |

### 4.3 目标回传时机

- 在搜索任务中识别到目标立即回传，标记为一般目标
- 在跟踪模式中，识别到目标后立刻跟随，但不回传目标，跟踪过程中也不再回传该目标，等待地面站MAV_CMD_ATTACK指令后再做处理，MAV_CMD_ATTACK的param1=0表示打击，此时回传目标信息并附字段为打击目标；param1=1表示忽略，说明地面人员确认该目标识别错误，无人机应回到原搜索路径继续执行任务；param1=2表示目标暂存，发送目标信息至地面并标注跟踪目标，然后无人机回到原航线去继续执行任务。
- 即查即打模式中，搜索到目标直接进入打击，此时回传目标并标记为打击目标。

## 五、打击任务双准入机制

### 5.1 任务序列式打击（机载任务规划准入）
1. 航点配置：打击任务区内固定2个航点
    - 航点1：目标发现点
    - 航点2：打击瞄准点（目标位置）
2. 多机多打击模式（参考9.2.6skill_params的formation定义）
    - 0：默认模式
    - 1：顺序惯序打击
    - 2：多机协同编队打击
3. 速度约束：进入打击任务区域后统一使用打击专属速度。

### 5.2 实时指令打击 Command No.8（MAV_CMD_ATTACK）
1. 响应前置条件：仅飞机处于**跟踪状态**时，机载才会响应本条打击指令；
2. 指令携带参数：包含打击速度（m/s），当前未包含后续协议修改。

## 六、多机协同通信心跳协议
### 6.1 互通数据内容
机载间交互信息包含：本机SN序列号、当前飞行模式、正在执行任务、GPS坐标。

### 6.2 多机协同包频率动态调度（按间距分级）
1. 基础默认心跳频率：基础帧率；
2. 间距 40m 以内：提升心跳至 5Hz；
3. 间距 20m 以内：提升心跳至 20Hz。

### 6.3 模式切换通信规则
地面站下发任务时，都会同时发送模式指令，确认飞机在任务区内是纯搜索，还是搜索后跟踪，还是即查即打。

## 七、下一阶段测试的搜索-跟踪-打击业务交互流程
### 7.1 任务分配阶段
1. 地面站配置搜索任务全部参数；
2. 选中目标飞机，完成搜索任务分配；
3. 地面站将任务流（可能包含多个任务）下发至对应机载单元。如果需要多无人机打击同一个目标，或者无人机集结任务，则需要每个无人机读取执行该打击或者集结任务的其他无人机，通过多机协同信息来完成协同打击的工作，或者在集结区等待全部集结完成（需设置最大timeout时间，可写死）后自动去执行下一任务。

### 7.2 机载执行搜索流程
1. 机载接收任务，沿`arrive_path`航线飞行至搜索任务区域；
2. 抵达任务区后，沿`skill_area_path`执行区域遍历搜索。是否打击或者跟踪或者只是识别到目标上报则根据MAV_CMD_SET_WORKMODE设置的无人机任务模式来确认。

### 7.3 目标识别是否进入跟踪上报
机载视觉识别到目标，如果是搜索跟踪模式，则自动切入跟踪状态，通过【6. 跟踪状态回传 TRACKING_STATE】报文向上上报本机跟踪状态。

### 7.4 地面站前端设备展示逻辑（与机载开发无关）
1. 设备列表中，处于跟踪状态的飞行器图标高亮闪烁区分；
2. 用户点击列表内跟踪飞机，跳转至该机详情页面，自动将全局第一视角切换为该机载摄像头画面；
    > 补充交互确认：若设备列表已预选该机，第一视角自动切换逻辑需与前端联调确认。

### 7.5 第一视角窗口交互（与机载开发几乎无关）
1. 画面内算法自动框选被跟踪目标；
2. 支持画面放大切换；
3. 窗口悬浮三个操作按钮：打击、忽略、暂存。

### 7.6 按钮指令下发与业务联动
统一使用【8. 跟踪模式下的打击 / 取消打击 MAV_CMD_ATTACK】报文下发指令，通过`param1`区分操作类型：
#### 7.6.1 打击按钮（param1=0）
1. `param2`：打击速度，单位 m/s；
2. 机载收到指令，执行打击动作；
3. 机载同步上报目标信息帧，目标`type=1`（被打击目标）；
4. 地面站处理：
    - 新增至全局目标列表；
    - 列表UI标记为被打击；
    - 地图图层目标图标同步展示打击标识。

#### 7.6.2 忽略按钮（param1=1）
1. 机载接收指令，终止目标跟踪；
2. 自动恢复原有搜索任务，返航至航线继续至未执行航点。

#### 7.6.3 暂存按钮（param1=2）
1. 机载接收指令，终止跟踪，恢复原有搜索任务，回到原航线继续至未执行航点；
2. 机载上报目标信息帧，目标`type=2`（被跟踪暂存目标）；
3. 地面站处理：
    - 新增至全局目标列表；
    - 列表UI标记为暂存跟踪；
    - 地图图层同步展示跟踪标识。

## 八、目标列表管理规范
### 8.1 目标类型枚举定义
| type值 | 目标分类     | 生命周期策略                 |
| ------ | ------------ | ---------------------------- |
| 1      | 被打击目标   | 永久保留，不自动删除         |
| 2      | 暂存跟踪目标 | 永久保留，不自动删除         |
| 3      | 普通搜索目标 | 支持时效自动清理（超时移除） |

### 8.2 普通搜索目标额外处理规则
普通目标（type=3）需增加聚类、去重算法，消除重复识别目标，机载端提高识别率降低误检律，同时通过目标定位算法尽量避免单个目标多次回传。

## 九、补充约束汇总
1. 弹射起飞后置任务强制校验，无后续任务禁止下发；
2. 所有任务强制携带速度参数，区分进场/区内两段速度；
3. 打击双路径：任务规划序列打击、跟踪状态实时指令打击；
4. 多机通信动态调频，距离越近心跳刷新率越高；
5. 目标三级分类，区分持久留存与自动清理对象，普通目标增加去重逻辑。
